# Night Shift v3 | A11Y contribution and evidence

**Lane:** A11Y (additional, non-overlapping lane after all 17 official lanes were taken)
**Branch:** `agents/v3-a11y-6f2b1`
**Baseline:** `rebuild/night-shift-v3-hd`
**Preview:** `previews/v3-a11y.html`
**Date:** 2026-11-08 AEDT

## Actual implementation

- `night-shift-v3/accessibility/controls.mjs`: optional, scene-neutral assistive controller. Configurable large-target assistance, with only unambiguous valid targets eligible for pointer snapping; keyboard focus/cycling and switch-step navigation; physical tap/drag/hold dispatch; high-contrast non-colour-only indications; reduced-motion options; persistent isolated preferences; Practice Shift preference without inventing completion or altering corporate scoring.
- `previews/v3-a11y.html` and `previews/v3-a11y-demo.mjs`: independently runnable, fullscreen Canvas2D office scene with three manual interactions (stamp the good form, drag evidence for Mira, hold the clock-out button), functional option panel and responsive staging. The intentional illustration is a contract demonstration, **not an HD-parity production scene**.
- `qa/v3-a11y-unit.test.mjs`: preference sanitation, unmodified default pointer behavior, ambiguous-target rejection, offscreen/bad-target rejection.
- `qa/v3-a11y-browser.py`: real Chromium interaction tests, viewport checks, console/network checks and real screenshot capture.

## Reproduction

From repository root:

```bash
python -m http.server 4173
# Navigate to http://localhost:4173/previews/v3-a11y.html
node --test qa/v3-a11y-unit.test.mjs
python -u qa/v3-a11y-browser.py
```

Python browser runner requires Playwright and installed Chromium (local evaluation used `/usr/bin/chromium`). Localhost navigation was blocked by the test environment's browser policy, so that runner actually fell back to `page.set_content` with *the same local HTML and inlined source modules*; assertions ran in Chromium, not a mocked DOM. This does **not** validate public hosting or Pages paths.

- **Unit tests:** 4 passed, 0 failed (Node test runner).

- **Interaction coverage:** keyboard stamp, physical pointer drag to destination, sustained hold, active state changes, error-free console/network checks and responsive fullscreen composition.

## Adapter integration (LEAD review required)

Import `createAssistiveControls` from `./accessibility/controls.mjs` in the host. Provide live semantic target enumerations (ids, labels, world x/y, action kind and optional drag endpoint), `getViewport`, and `dispatch` that uses the same scene pointerDown/pointerMove/pointerUp/cancelPointer paths as ordinary input. Wire its optional `onPause` to the shared gameplay clock, and read Practice selection only when creating the *next* run. Do not replace the existing RENDER lane input mapping or alter systems ledger events. The adapter supports optional keyboard/switch navigation as supplemental interaction; mouse/touch remain first-class.

## GDD and release truth

Addresses optional high-contrast, large target, keyboard/switch support, reduced motion and explicit practice preferences without silently changing Standard scoring. Existing 16-card, 12-run, five promotions/directives, eight perks and two bosses remain mandatory, but **this lane does not implement them**. No existing game release or another lane's code was changed.

**Comparison to Night Shift HD:** the scene demo borrows its cinematic warm-paper/teal/gold staging and fullscreen canvas, but is demonstrably simpler in character expressiveness, animation and music. It must not be treated as a new release or evidence of an HD-beating game.

## Known blockers and remaining checks

- Full integrated v3 scenes must provide a semantic target list and explicit pause handling; LEAD must approve the adapter contract.
- Single-switch step navigation works; timed automatic scanning has not been implemented.
- This is an auxiliary preview, not a complete game or human playtest.
- Hosted Pages navigation and persistent CI screenshots remain unverified; two actual browser captures are now GitHub-tracked in this PR.
- Sound, all 16 cards, both bosses, promotion intermissions and final receipt require full integration/acceptance by respective owners.

## Follow-up hardening and browser QA (8 November 2026, after initial delivery)

Resumed this PR and inspected the real scene/action code plus Chromium frames. Expanded QA reproduced an Escape event-propagation defect: cancelling a virtual drag also toggled the host pause listener. Fixed by consuming handled assistive key events. Also fixed stale virtual holds across timed scene transitions, switch focus trapping after Options closes, Shift+Arrow five-step movement while still dispatching genuine pointerMove events, and a stale hold alert hiding the replay button.

The independently runnable preview now has a deliberate CLOCK IN AGAIN action, resets progress without duplicate credit, applies the player's explicit Standard/Practice preference only at the next run, and hides live timer/hearts from its final receipt. Updated browser tests perform two full runs at each of 1920×1080 and 650×800: pointer+keyboard mixed first, switch/keyboard-only replay second, including genuine drag, cancelled drag without reward, manual release, options-paused clock, reset and pointer cleanup.

**Rerun evidence:** 4/4 Node unit tests; **62/62 Chromium assertions**: 27 at 1080p, 27 at portrait, 4 at 4K DPR2 and 4 at ultrawide. The four viewports were run separately to avoid software-rendered 4K scheduling stalls. Localhost navigation remained policy-blocked: the real Chromium tests used identical source loaded through the inline fallback. The test runner itself captures new keyboard-file and keyboard-victory screenshots, and the corrected portrait victory frame was personally inspected. These new images currently reside in the local run artifacts; the two original real Chromium screenshots already in this PR remain valid baseline evidence. Public Pages and integrated campaign/human QA remain outside this lane's verified scope.
